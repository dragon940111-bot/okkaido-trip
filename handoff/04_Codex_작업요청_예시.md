# Codex 작업 요청 예시 (복사해서 쓰기)

저장소: **dragon940111-bot/okkaido-trip**
규칙: 저장소 맨 위 `AGENTS.md`를 따름. 원본은 `source/`이고, 빌드는 `source/tools/build_all.sh`로 함.

- 모든 요청 끝에 아래 **공통 꼬리말**을 붙이면 안전함.
- 날짜·끼니·가게 이름은 `여행정보_전체.md`에 적힌 그대로 쓰는 게 정확함(일본어 이름 + 한글 이름).

---

## 공통 꼬리말 (모든 요청 끝에 붙이기)

```
AGENTS.md를 먼저 읽고 그 규칙대로 해 줘.
- 원본(source/)을 고친 뒤 build_all.sh로 다시 빌드해서 사이트 파일(맨 위 폴더)까지 갱신해.
- 페이지 글은 한국어로만. 설명문 말투는 "~했음/~함/~됨". 가게 정보(영업·가격·팁)는 지어내지 마. 모르는 값은 "(확인 못 함)".
- 빌드 후 확인할 것: 스크립트 오류 없음, 휴대폰 폭(390px)에서 옆으로 넘침 없음, 바뀐 곳이 실제로 보임.
- sw.js 버전이 바뀌어야 친구들 폰에 "업데이트됨"이 뜨니, 빌드가 sw.js를 새로 만들었는지 확인해.
- 바꾼 내용을 한국어로 3–5줄 요약해서 PR 설명에 적어 줘.
```

## 1. 식당 바꾸기 (메인 ↔ 대안)

```
11/4(DAY 3) 점심 메인을 지금의 伊達 翁(다테 오키나)에서, 같은 끼니 대안에 있는 [대안 가게 일본어 이름]으로 바꿔 줘.
- 원래 메인(翁)은 대안 목록 맨 앞으로 옮겨.
- 시간표 시각과 이동 시간은 그 대안 카드의 "이 가게로 바꾸면" 문구를 따라 고쳐.
- 맛집만 모아 보기, 미리 할 것(예약 목록)에도 같이 반영해.
- 지도 번호·지도 그림은 건드리지 말고, 바뀐 점을 PR 설명에 적어 줘.
(공통 꼬리말)
```

## 2. 시간 바꾸기

```
11/2(DAY 1) 야식(징기스칸) 시작 시각을 20:30에서 21:00으로 바꿔 줘.
- 그 줄 앞뒤 이동 시간도 자연스럽게 맞춰.
- 미리 할 것의 예약 항목에 적힌 시각도 같이 바꿔.
(공통 꼬리말)
```

## 3. 공지 추가 (시험용으로도 좋음)

```
페이지 맨 위 제목 바로 아래에 공지 한 줄을 넣어 줘:
"📢 11/3 저녁 덴푸라 예약 17:00 확정했음 (경일)"
- 눈에 띄되 너무 크지 않게, 기존 색 변수를 써서 라이트·다크 모두 보이게.
- 운전 가이드북 페이지에는 넣지 마.
(공통 꼬리말)
```

공지 지우기:

```
방금 맨 위에 넣은 공지 줄을 지워 줘. (공통 꼬리말)
```

## 5. 가게 정보 고치기 (휴무·영업시간 등)

```
[가게 일본어 이름] 카드의 영업시간을 "[새 영업시간]"으로, 휴무를 "[새 휴무]"로 고쳐 줘.
- 이 가게가 대안 일정(A–G)이나 외곽 맛집에도 나오면 거기도 같이 고쳐.

(공통 꼬리말)
```

## 6. 사진 추가 (주의)

사진 추가는 Codex로 하기엔 실수가 나기 쉬움. 가능하면 **Claude에서** 하는 걸 권함.

- 사진 파일 정리, 이미지 크기, 사진 목록 등록, 공개판 사진 묶음 다시 만들기를 다 맞춰야 하기 때문임.
- 꼭 Codex로 할 때만 아래처럼 요청함.

```
[가게 일본어 이름] 카드에 사진 1장을 추가해 줘. 사진 파일은 이 PR에 첨부한 [파일명]이야(가게·촬영자 허락 받은 사진).
- AGENTS.md의 "사진 추가" 절차를 그대로 따르고, 다른 가게 사진 순서는 건드리지 마.
- 빌드 후 그 카드에 사진이 실제로 보이는지, 사진 묶음(p/)이 새로 만들어졌는지 확인해.
(공통 꼬리말)
```

## PR이 만들어진 뒤 (경일이 할 일)

1. 휴대폰 **GitHub 앱** → okkaido-trip → **Pull requests** → 새 PR을 엶.
2. 설명과 바뀐 파일을 훑어봄. 이상하면 Codex에 "이 PR 여기 고쳐줘"라고 다시 요청함.
3. 괜찮으면 **Merge pull request** → **Confirm merge**.
4. 1–2분 뒤 공개 주소에서 "업데이트됨" → [업데이트하기]를 누르고 확인함.
