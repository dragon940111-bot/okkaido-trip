## 2단계. ChatGPT 프로젝트 만들기

1. ChatGPT 앱(또는 chatgpt.com)에서 **프로젝트 → 새 프로젝트**를 누르고, 이름을 **"홋카이도 여행"**으로 함.
2. 프로젝트 안 **파일 추가**에서 1단계 파일을 올림(1–3번 먼저).
   - 프로젝트에 올릴 수 있는 파일 개수 제한은 직접 보지 못함.
   - 다 안 들어가면 1–3번만 올려도 됨.
3. 프로젝트 **지시사항(Instructions)** 칸에 `01_프로젝트_지시사항.md`의 블록 안 글을 붙여 넣음.
4. 그 프로젝트 안에서 **Work**로 새 대화를 열고, `02_첫메시지_프롬프트.md`의 블록을 그대로 보냄.
5. 답을 보고 틀린 데가 있으면 바로잡아 줌. 특히 날짜별 메인 식당과 예약 목록을 확인함.

## 3단계. 음성 시험 (출발 전, 한국에서)

1. 같은 프로젝트 대화 안에서 **음성 모드**를 켬.
2. 이렇게 물어봄.
   - "11월 4일 점심 메인 어디야?"
   - "대안은?"
   - "그 주변에 뭐 있어?"
3. 답이 **伊達 翁(다테 오키나) 수타 소바**와 그 대안들이면 정상임.
4. 엉뚱하게 답하면 음성 모드가 파일을 못 읽는 것임.
   - 음성 모드가 프로젝트 파일을 참고하는지는 직접 보지 못함.
   - 이때는 글로 물어보거나, 음성으로 묻기 전에 "여행정보_전체.md 기준으로 답해"라고 먼저 말해 봄.
5. "오늘 며칠이야? 일본 시간으로."도 물어서 날짜 판단이 맞는지 확인함.

## 4단계. 공유 페이지 수정용 Codex 연결 (선택)

Codex가 경일의 요금제에서 되는지, 메뉴 이름이 정확히 무엇인지는 직접 보지 못함.

1. ChatGPT에서 **Codex**를 열고 **GitHub 연결**을 함. GitHub 계정 `dragon940111-bot`으로 로그인하고, 저장소 **dragon940111-bot/okkaido-trip** 접근을 허락함.
   - 로그인은 경일이 직접 함.
2. Codex 환경(Environment)을 만들 때 저장소로 okkaido-trip을 고름.
   - 빌드 준비 명령은 저장소의 `AGENTS.md`에 적혀 있음. Codex가 알아서 읽음.
3. **작은 수정 시험:** `04_Codex_작업요청_예시.md`의 "공지 추가" 요청을 그대로 보냄.
4. Codex가 끝나면 **PR(변경 요청)** 이 만들어짐.
5. 휴대폰 **GitHub 앱** → 저장소 okkaido-trip → **Pull requests** → 그 PR을 엶 → 바뀐 내용 확인 → **Merge pull request** → **Confirm merge**.
6. 1–2분 뒤 https://dragon940111-bot.github.io/okkaido-trip/ 를 열면 "업데이트됨"이 뜸. [업데이트하기]를 누르고 공지가 보이면 성공임.
7. 시험 공지는 같은 방법으로 지우라고 Codex에 시키면 됨. 예: "방금 넣은 공지 지워줘".

## 5단계. 동행자 폰 (카톡으로 이미 보낸 링크)

1. 링크 https://dragon940111-bot.github.io/okkaido-trip/ 를 사파리(아이폰)나 크롬(안드로이드)에서 엶.
2. **홈 화면에 추가**를 함.
   - 아이폰: 공유 → 더 보기(⌄) → 홈 화면에 추가
   - 안드로이드: ⋮ → 홈 화면에 추가
3. 처음 열 때 "다운받는 중 N%" → "준비 완료 ✓"가 될 때까지 기다림. 그다음부터는 인터넷 없이도 다 보임.
4. 페이지가 바뀌면 열 때 "업데이트됨"이 뜸. [업데이트하기]를 누르면 됨.

## 6단계. 일본에서

| 상황 | 할 일 |
|---|---|
| 인터넷 됨 | ChatGPT 프로젝트 대화에서 음성으로 질문 |

| 큰 수정, 또는 Codex가 안 될 때 | 휴대폰 **Claude 앱**에서 기존 대화를 열고 부탁함. Claude는 공개 주소까지 고쳐서 올릴 수 있음 |
